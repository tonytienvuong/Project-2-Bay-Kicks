The API

Everything lives under /api. Requests and responses are JSON; the routes also accept urlencoded bodies so a plain HTML form can post to them.

Products

Method and pathWhat it doesAnswers
GET /api/products Whole catalogue from the products collection 200 — array of 25 products
GET /api/products/:id One product by its numeric id 200 — product · 404 if there is no such id

Cart — the Express session

No cart id is ever sent by the browser. The cart is req.session.cart, found through the signed session cookie, so a cart belongs to a browser, not to a login.

Method and pathBodyAnswers
GET /api/cart — 200 {items, count, subtotal}
POST /api/cart {productId, size, color, qty} 200 {items, count} · 400 unknown product, missing size, bad quantity
PUT /api/cart/:itemId {qty, size, color} 200 {items, count} · 404 no such line · 400 quantity out of range
DELETE /api/cart/:itemId size and color when the product is in twice 200 {items, count} · 404 no such line

:itemId is the product id. Because the same product can sit in the cart in two sizes, size and color identify which line is meant.

Health

GET /api/health reports whether the server is up, whether the database is connected, how many lines are in the session cart and who is signed in. It is the fastest way to tell a broken deploy apart from a broken browser session.

Errors are JSON, always. An unknown /api path answers 404 {"error":"No such API route: ..."} rather than the React page, so a typo in a fetch() is visible instead of silent.
