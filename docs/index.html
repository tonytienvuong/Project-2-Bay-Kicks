Bay Kicks — a full-stack sneaker storefront

A React single-page app talking to a Node + Express REST API, with users, session carts and orders stored in MongoDB Atlas. Group 7 — Tien Vuong, Benjamin Samok, Patrick Simpauco. CS351-02-1, Dr. Grewe, Fall 2026.

Front end

React 19 + Vite, Bootstrap 5. Product list, product detail, cart, account dashboard and checkout — all one page that swaps views.

Back end

Express 5 with routes → controllers, `body-parser`, `express-session`, and one shared MongoClient opened in `startServer()`.

Data

MongoDB Atlas: products, users, orders. Passwords are bcrypt hashes; cards are stored as type + last four only.

The customer flow

/createAccount   form → POST /api/accounts        → "Account created. Please log in."
/account         form → POST /api/login           → dashboard: your info, edit, orders, log out
/shop            GET  /api/products               → 25 products from MongoDB
/product/:id     GET  /api/products/:id           → pick size + colour, POST /api/cart
/cart            GET  /api/cart                   → quantity +/−, remove
/checkout        GET  /api/checkout               → subtotal, 9.5% tax, total
                 POST /api/orders                 → order document, confirmation page
Where the state lives. The cart and the signed-in user are held in the Express session on the server, not in the browser's localStorage. The React app asks GET /api/cart after every change and mirrors what the server says.

Points of interest for anyone reading the code

  • The cart re-prices every line from the products collection on each call, so a tampered price in the request body cannot change a total.
  • Creating an account checks login and email uniqueness in a single query, and re-runs all the client-side validation on the server.
  • The order document stores userId — the MongoDB _id of the user who placed it — which is the reference back to users.
  • Checkout refuses an empty cart, and the cart is emptied only after the order insert succeeds.
