Server files, one at a time

server/server.js

startServer() is the whole startup story: load .env, connect to Atlas once, seed products if the collection is empty, then app.listen(PORT). The project page asks for the connection to be made here and reused, rather than opened per request. The same file registers the shutdown handler that closes the pool on SIGINT/SIGTERM.

server/app.js

Wiring only, in five ordered steps: bodies, sessions, /api routes, the static React build, then the index.html fallback. Two small things worth noticing: a JSON 404 for unknown API paths, and the four-argument error handler at the bottom that turns anything a controller passes to next(err) into a JSON error instead of a crash.

server/db/databaseConnection.js

connectToDatabase() creates the client with ServerApiVersion.v1 and pings admin straight away, so a bad password or a blocked IP fails at startup with a readable message instead of failing later inside a controller. getCollection(name) hands out users, products and orders; getConnectionState() is what /api/health reports.

server/middleware/requireLogin.js

Fourteen lines that decide whether a protected route runs: if req.session.user is missing, answer 401 with a message; otherwise call next(). Mounted on /api/account, /api/checkout and every /api/orders route.

Rubric item → the code that earns it

RequirementWhere it is implemented
MongoDB database with users and orders databaseConnection.js + the collections used in every controller; the database name comes from MONGODB_DB
createAccount, validated again on the server, login and email unique accountController.validateSignup() then createAccount() — one $or query for both uniqueness checks
Login checked against the stored password accountController.login() — bcrypt compare, then req.session.user = {_id, login, email, firstName}
Add to cart in the Express session, count on the nav bar cartController.addToCart() writes req.session.cart; NavBar.jsx renders count from GET /api/cart
Cart page with quantity up/down and remove cartController.updateCartItem() and removeCartItem(); CartView.jsx / CartItem.jsx drive them
Checkout refuses an empty cart, writes an order with a user reference, shows the total with tax orderController.createOrder() — re-prices from products, inserts userId + items + subtotal/tax/total, empties the session cart, returns the order; CheckoutView.jsx renders the confirmation
Password security bcrypt.hash() on create, bcrypt.compare() on login — passwordHash is the only password-shaped field in users
Card data not stored orderController.readPayment() keeps cardType and last4 and drops the rest
One deploy serving both halves Dockerfile — stage 1 runs npm run build, stage 2 ships server/ and the built client/dist

Client files worth opening first

client/src/api.js

Everything the browser sends lives here, one function per endpoint, each returning parsed JSON and throwing the server's error message when a response is not ok. When a form "does nothing", this file is where to look first.

client/src/App.jsx

Holds view, the product list, and the cart summary; passes them down as props. It reads window.location.pathname on first load so /shop, /cart and /checkout open the right view.

client/src/components/ProductDetailView.jsx

The one place a cart line is created. The Add to Cart button stays disabled until both a size and a colour are chosen — matching the product page rule from Project 1 — and the quantity is clamped to what the product has in stock.
