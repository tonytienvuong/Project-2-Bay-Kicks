Run it, deploy it

Two commands locally, one deploy to Cloud Run. The only thing you must supply is a MongoDB Atlas connection string.

Prerequisites

  • Node.js 20 or newer
  • A MongoDB Atlas account with a free M0 cluster, a database user, and this machine's IP allowed
  • The Google Cloud SDK (gcloud), signed in, for the deploy

1. Configure

Copy the example settings file and fill in the connection string:

cp .env.example .env
MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority
MONGODB_DB=baykicks
SESSION_SECRET=some-long-random-string
PORT=3000

.env is in .gitignore and .dockerignore — it never goes to GitHub and never goes into the image.

2. Install, build, run

npm install
npm run build      # builds the React app into client/dist
npm run server     # Express serves the API and the built app on :3000

Open http://localhost:3000. On the first start the products collection is seeded from server/data/products.json if it is empty; npm run seed does the same thing on demand.

For live reload while editing React, run npm run dev in a second terminal — Vite proxies /api to port 3000, so both halves stay in sync.

3. Deploy to Cloud Run

One service serves the API and the built React app; Atlas stays external.

gcloud run deploy bay-kicks --source . \
  --region us-central1 --allow-unauthenticated \
  --env-vars-file /tmp/bay-kicks-env.yaml

That YAML file holds the same three settings from .env (MONGODB_URI, MONGODB_DB, SESSION_SECRET) and is deleted after the deploy.

Why a Dockerfile instead of just the source. client/dist is gitignored, so a deployed copy of the repository has no built React app. The Dockerfile's first stage runs npm run build inside the image, and the second stage ships only the server, its production dependencies and the built files.

4. Check the live service

curl -s https://<service-url>/api/health          # {"ok":true,"db":{"connected":true,...}}
curl -s -o /dev/null -w '%{http_code}\n' https://<service-url>/api/products   # 200

If the page loads but every product call fails, the container cannot reach Atlas: add 0.0.0.0/0 to Atlas → Network Access for the length of the demo and remove it afterwards. If /api/health says the database is not connected, read the reason it prints — it carries the driver's own message.

Troubleshooting

SymptomCause
Blank page, or 404 on /assets/*.js The React build is missing from the image — rebuild with the Dockerfile
Every page shows the home view Normal for a URL other than the ones App.jsx reads; navigate from inside the app
Cart empties after a restart Expected — the session store is in memory
401 on /api/checkout Not signed in; sign in first, checkout needs a user to attach the order to
